# Ouverture automatique du panneau Inspect — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Le panneau Inspect s'ouvre seul à la première écriture de code de la session, quand l'option `autoOpen` du mod est active.

**Architecture:** Un champ `userConfig` booléen dans le manifeste, lu par `register(on, options)`. Le hook `tool.call` existant ouvre le panneau après le premier `Edit`/`Write`/`NotebookEdit` réussi ; un booléen `hasAutoOpened` dans `$.state` garantit une seule ouverture par session.

**Tech Stack:** Module de hooks Claude Code (TypeScript/JSX, API `claude-code`), tests avec `claude-code/testing`.

**Spec:** `docs/superpowers/specs/2026-11-23-auto-open-design.md`

## Global Constraints

- Option : `autoOpen`, booléen, défaut `false`.
- Outils déclencheurs : `Edit`, `Write`, `NotebookEdit`. `Bash` ne déclenche jamais l'ouverture ; il continue de rafraîchir un panneau déjà ouvert.
- Une ouverture automatique au plus par session ; `/inspect` à la main compte comme ouverture faite.
- L'ouverture ne retarde jamais et ne fait jamais échouer l'appel d'outil.
- Les écritures des sous-agents comptent (pas de filtre sur `agentId`).
- Textes visibles par le dev en français, comme le reste du mod.
- Version du mod : `0.4.0`.
- Pas de `git commit` sans l'accord du dev : chaque étape « Commit » attend son feu vert.

## Review Focus

1. Deux `Edit` lancés en parallèle dans le même pas : une seule ouverture (le drapeau est posé avant `$.ui.open`). Test en tâche 1.
2. `/inspect` tapé à la main, puis un `Edit` : pas de seconde ouverture. Test en tâche 1.
3. `Edit` hors d'un dépôt git : pas d'ouverture, drapeau non posé (choix de Claude, hors spec : un panneau qui dit « Pas un dépôt git » est du bruit). Test en tâche 1.
4. `$.ui.open` qui échoue : l'appel d'outil rend quand même son résultat. Test en tâche 1.
5. `Edit` d'un sous-agent (`agentId` présent) : le panneau s'ouvre. Test en tâche 1.

```ts
test('autoOpen: the first successful Edit opens the pane and fills the list', AUTO, …)
// $.tool.call({ tool: 'Edit', file_path: '/repo/src/a.ts', old_string: 'a', new_string: 'b' })
// expect(opens).toEqual(['code-inspector'])
// mount(PANE) → find Text /src\/a\.ts/ défini

// deux Edit l'un après l'autre → expect(opens.length).toBe(1)

test('autoOpen: two Edits at once open it once', AUTO, …)
// await Promise.all([Edit, Edit]) → expect(opens.length).toBe(1)

test('autoOpen: /inspect by hand counts as the opening', AUTO, …)
// await $.command.run(inspect()) ; Edit → expect(opens.length).toBe(1)

test('autoOpen: Bash alone opens nothing', AUTO, …)
// $.tool.call({ tool: 'Bash', command: 'ls' }) → expect(opens).toEqual([])

test('autoOpen: a failed Edit opens nothing', AUTO, …)
// isToolError: true → expect(opens).toEqual([])

test('autoOpen: nothing opens outside a git repository', AUTO, …)
// isRepo: false → expect(opens).toEqual([])

test('autoOpen: a subagent Edit opens the pane', AUTO, …)
// Edit avec agentId: 'a1' → expect(opens).toEqual(['code-inspector'])

test('autoOpen: an opening that fails leaves the tool call its result', AUTO, …)
// failOpen: true → le résultat de $.tool.call est défini, rien n'est levé

test('autoOpen off by default: an Edit opens nothing', …)
// sans options → expect(opens).toEqual([])
```

- [ ] **Step 5: Implémenter l'ouverture**

Dans `hooks/register.tsx` :

- `autoOpen($)` : ne fait rien si `hasAutoOpened` vaut déjà `true` ou si `locate($)` rend `undefined` ; sinon pose `hasAutoOpened` à `true`, **puis** appelle `$.ui.open({ id: PANE, title: TITLE })` et `refresh($)`. Le test et la pose du drapeau se font sans `await` entre les deux lectures concurrentes possibles : poser le drapeau dans le même `update` qui le lit (l'`update` rend l'ancienne valeur ou le module garde une promesse en cours), pour que deux appels simultanés n'ouvrent qu'une fois.
- `register = (on, options)` : `const isAutoOpen = options.autoOpen === true`.
- Hook `tool.call`, après `next(e)` : si `isAutoOpen`, que l'outil est dans `OPENING_TOOLS` et que l'appel n'est pas en erreur, lancer `void autoOpen($).catch(() => undefined)` à la place du rafraîchissement conditionnel ; sinon garder le chemin actuel (`WRITING_TOOLS` → rafraîchir si ouvert).
- Hook `command.run` : poser `hasAutoOpened` à `true` avant `$.ui.open`.
